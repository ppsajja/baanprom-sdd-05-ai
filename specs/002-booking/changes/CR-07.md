## ขนาดและทางเลือก

- ขนาดงานโดยประมาณ: ตอนนี้ 0 task (เอกสารอย่างเดียว) หลังอนุมัติคาดว่า 6 ถึง 9 task ใหม่ (1 task ต่อ REQ ที่มีโค้ด: OP-005, QA-010, SEC-010, SEC-011, PRV-010 และ task เอกสารสำหรับ OP-001, OP-006, OP-007, CMP-001) test ที่ต้องรันซ้ำ: ทั้งชุด 3 feature ตัวเลขนี้เป็นการประมาณของ AI ทีมต้องตรวจตอน /tasks
- ทางเลือกที่พิจารณา
  - ก เสนอทั้ง 9 ข้อเป็น Constraint กลางรุ่น 1.1 ใน CR เดียว (เลือก) เพราะทุกข้อมาจากการทบทวนรอบเดียวกัน และทุกข้อใช้กับทุก feature ถ้าแยก CR ตารางผลกระทบจะซ้ำกัน 9 ชุด
  - ข ใส่เฉพาะ feature ที่เจอเหตุ (REQ-QA-010 ใน 002 และ 004, REQ-SEC-010 ใน 003 และ 004): ปฏิเสธ เพราะเป็นข้อที่ feature ถัดไปต้องใช้ด้วย จะกลับไปปัญหาเดิมที่ CR-04 แก้ไปแล้ว
  - ค แก้โค้ดทันทีพร้อม CR: ปฏิเสธ เพราะยังไม่มีผู้อนุมัติ และตัวเลขหลายตัวยังเป็น Q การเขียนโค้ดตอนนี้คือการเดาแทนเจ้าของธุรกิจ (กฎข้อ 2)
  - ง เลื่อนทั้งหมดไป R2: ปฏิเสธ เพราะเหตุการณ์ B ทำให้ลูกค้าเสียเงินจริง และ REQ-PRV-010 เป็นสิทธิ์ตามกฎหมายที่ต้องมีก่อนเปิดให้ลูกค้าจริง ทีมเสนอให้อย่างน้อย REQ-QA-010 และ REQ-SEC-010 เป็นเงื่อนไขก่อนเปิด R1 (เพิ่มจาก Q-26, Q-31, Q-34 ที่มีอยู่)

## ภาคผนวก ก: misuse case

misuse case คือ use case ที่เขียนจากมุมของคนที่ตั้งใจใช้ระบบผิด เขียนเหมือน use case ปกติ แต่ "เป้าหมาย" คือสิ่งที่เราไม่อยากให้เกิด และปิดท้ายด้วยสิ่งที่ระบบต้องทำเพื่อกัน ซึ่งกลายเป็น REQ

MU-01 ยกเลิกงานของคนอื่น
ตัวละคร: ลูกค้าที่ลงทะเบียนแล้ว (ไม่ใช่เจ้าของงาน)
เป้าหมายของเขา: ให้ช่างว่างในช่วงเวลาที่ตัวเองอยากได้
ขั้นตอน:
  1. จองงานของตัวเอง ได้เลขงาน 1025
  2. เดาว่างานก่อนหน้าคือ 1024
  3. ส่งคำขอ POST /jobs/1024/cancel
  4. ระบบยกเลิกงาน 1024 และคืนมัดจำให้เจ้าของงานนั้น
ผลเสีย: ลูกค้าอีกคนเสียคิว ช่างเสียงาน บ้านพร้อมเสียความเชื่อถือ
สิ่งที่ระบบต้องทำเพื่อกัน: ตรวจว่าผู้ส่งคำขอเป็นเจ้าของงาน 1024 ถ้าไม่ใช่ ตอบ 403 และบันทึกความพยายาม
ข้อกำหนดที่เกิด: REQ-SEC-010

หมายเหตุของทีม: เลขงาน 1024 และ 1025 เป็นตัวอย่างในเรื่องเล่า ไม่ใช่ค่าในระบบ ขั้นที่ 4 เป็นสิ่งที่เกิดกับ POST /jobs/{id}/cancel ของ 002 ซึ่งรับ cancelled_by โดยไม่ตรวจว่าใครส่ง (plan.md ของ 002 ข้อ 4) ส่วน POST /jobs/{id}/customer-cancel ของ 004 ตรวจ customer_id แล้ว (AC-08-01) แต่ยังตอบ 404 และไม่บันทึกความพยายาม (Q-47)
